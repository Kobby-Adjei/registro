# Contributing to Registro

## Branching

Create a branch for each task. Use clear names such as:

- `feature/authentication`
- `feature/event-creation`
- `feature/event-discovery`
- `fix/registration-validation`
- `docs/database-design`

## Commits

Keep commits focused and use descriptive messages, for example:

- `feat: add event creation form`
- `fix: prevent duplicate registrations`
- `docs: add database schema`
- `test: add registration validation tests`

## Pull Requests

Before merging into `main`:

1. Make sure the feature works locally.
2. Keep the pull request focused on one task.
3. Explain what changed and how it was tested.
4. Request review from at least one teammate when practical.
5. Resolve review comments before merging.

## Project Scope

Prioritize the core event lifecycle before optional features. New ideas should be added as issues first so the team can agree on scope before implementation.
